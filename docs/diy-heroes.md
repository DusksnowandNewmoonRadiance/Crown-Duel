# DIY 角色系统 · 说明书

> 目标：玩家可以自己做卡牌师，**不用再等官方调平衡**；代价是 DIY 角色和原版池**完全分开**。
> 手机/平板可用：≤960 宽时工坊自动变单列、底部角色条吸底，触摸目标 ≥38px；界面已跟随 v3.1.0「气质升级」与 v3.2.0「特效重做」的设计语言：工坊复用同一套 tokens、卡面预览用新的程序化插画、DIY 角色在主页封面 / 大厅 / 房间座位统一带 DIY 徽章。
> 官方只维护一个示例角色「苍蓝」，其余全部由玩家自己上传。

## 1. 两个池子

| | 原版池 | DIY 池 |
|---|---|---|
| 角色 | 苏苏 / 字母 / 七星 / 核弹 / 猪瘟鱼 / 八幡 / 045 / 下水 / 绘梨衣 / 白猫 | 玩家上传的角色 + 内置示例「苍蓝」 |
| 房间 | 原版房间（`pool: vanilla`，默认） | 允许 DIY 的房间（`pool: diy`） |
| 能否混用 | **不能**。DIY 角色进不了原版房间 | 可以：DIY 房间里也能选原版角色 |

建房时按钮上是「原版房间 / 允许 DIY」，房间列表里 DIY 房间带 `DIY` 标记；快速匹配只会和同池的人匹配。

服务端是**硬约束**：客户端传了 DIY 角色进原版房间，会被直接拒绝并返回中文错误，不是靠前端藏起来。

几个容易踩的点：

- **快速匹配只排原版房间**，DIY 只能靠「创建 / 加入允许 DIY 的房间」。
- **单人练习、卡组页、图鉴只列原版 10 位**，所以想试玩苍蓝，要开一个允许 DIY 的房间（或直接用 `node winrate.js` 在本地跑）。
- 在大厅可以先点选 DIY 角色，但没进 DIY 房间时服务端会拒绝；前端会把选择暂存，进到 DIY 房间后自动换回来。
- 「更新自己的角色」目前 = **删掉再传**（同名上传返回 409），UI 里有提示。

## 2. 上传一个角色

### 2.1 网页

大厅 →「DIY 工坊」：

1. 左边是**角色信息**（名字、血量、阵营、主题色、一句话风格）；
2. 中间是**卡牌列表**，点「加一张牌」填：费用、类型（单位/法术）、攻击/生命、机制、张数、携带上限；
3. 右边是**实时预览**（按当前 UI 的卡面渲染）；
4. 「上传」后服务器会校验，失败会在列表里逐条标红；
5. 上传成功会出现在「DIY 角色」列表里，建房时选「允许 DIY」就能用。

### 2.2 接口

```
GET    /api/diy/catalog              机制目录 + 各项限制
GET    /api/diy/heroes               角色列表（摘要）
GET    /api/diy/heroes/:name         单个角色的完整定义
POST   /api/diy/heroes               上传（body: {"hero": {...}}，头 x-diy-owner: <你的匿名 id>）
DELETE /api/diy/heroes/:name         删除自己上传的角色（内置角色不可删）
```

上传示例：

```bash
curl -X POST http://你的地址/api/diy/heroes \
  -H "content-type: application/json" \
  -H "x-diy-owner: 6f1c...你的匿名 id" \
  -d '{"hero":{"name":"试验品","hp":30,"color":"#5ab4ff","cards":[
        {"id":"t1","name":"试验兵","cost":1,"kind":"unit","atk":2,"hp":2,"n":4,"limit":4},
        {"id":"t2","name":"试验术","cost":2,"kind":"spell","effect":"draw2","n":4,"limit":4}
      ]}}'
```

返回：

```json
{"ok": true, "name": "试验品"}
{"ok": false, "errors": ["卡牌种类必须是 8~24 张（当前 2）"]}
```

## 3. 角色 JSON 格式

```json
{
  "schema": 1,
  "name": "苍蓝",
  "faction": "神谕诸国 · 架子班",
  "style": "神系召唤 · 抽牌续航 · 后期爆发",
  "hp": 30,
  "color": "#5ab4ff",
  "cards": [
    {"id":"blue_believer","name":"苍蓝·信徒","cost":1,"kind":"unit","atk":2,"hp":1,"text":"","art":"◇","n":4,"limit":4},
    {"id":"blue_prayer","name":"苍蓝·祷文","cost":1,"kind":"spell","effect":"draw1","text":"抽 1 张牌。","art":"✧","n":4,"limit":4}
  ]
}
```

### 角色字段

| 字段 | 必填 | 限制 | 说明 |
|---|---|---|---|
| `name` | ✔ | 1~12 字，全服唯一，不能和原版角色重名 | 同时是内部 id |
| `hp` | ✔ | 20~50 | 英雄血量（原版多在 30~35） |
| `faction` | | 0~16 字 | 显示用阵营 |
| `style` | | 0~40 字 | 一句话风格，选角界面显示 |
| `color` | | `#RRGGBB` | 主题色，卡面/边框会用它 |
| `cards` | ✔ | 8~24 种 | 所有卡的携带上限合计 ≥ 40，否则组不出卡组 |

### 卡牌字段

| 字段 | 必填 | 限制 | 说明 |
|---|---|---|---|
| `id` | ✔ | 小写字母开头，`a-z0-9_`，2~32 位，角色内唯一 | 卡牌代码 |
| `name` | ✔ | 1~14 字 | 卡名 |
| `cost` | ✔ | 0~10 | 费用 |
| `kind` | ✔ | `unit` / `spell` | 单位 / 法术 |
| `atk` / `hp` | 单位必填 | 0~20 / 1~30 | 单位身材 |
| `effect` | 法术必填 | 见下方机制表 | 机制 id |
| `text` | | 0~90 字 | 卡面描述，留空会用机制默认文案 |
| `n` | ✔ | 1~4 | 官方推荐卡组里的张数 |
| `limit` | ✔ | 1~4 | 携带上限（稀有度自动按上限推导：4 普通 / 3 稀有 / 2 特殊 / 1 精英） |
| `art` | | 1~2 字 | 卡面角标（emoji 也可以） |
| `charge` / `taunt` / `ignoreTaunt` | | 布尔 | 冲锋 / 嘲讽 / 无视嘲讽 |
| `strikes` | | 2~3 | 每回合可攻击次数 |
| `lifespan` | | 1~3 | 限时：N 回合后消散 |

## 5. 内置示例「苍蓝」

`shared/diy-builtin.js` 里只有这一个角色，来自作者的 Duel 版本：30 血、17 张卡，低费信徒撑场 + 大量抽牌 + 圣堂/圣座嘲讽 + 终焉直伤，靠治疗和护甲拖到后期。

原版苍蓝的 5 个专属机制（神罚抽到自动、神谕壁垒、神罚共鸣、圣光牵引、机械眼）已经作为通用机制进白名单，任何 DIY 角色都能用；苍蓝本人就是按原版手感重写的。

## 6. 平衡与使用建议

- **DIY 不进原版池**，所以不用担心污染天梯/匹配数据，官方也不需要为 DIY 角色调平衡。
- DIY 角色强度差异会很大（30 血 + 一堆直伤也能上传），这是设计上的自由；房间是自愿进入的。
- AI 对 DIY 角色只会用通用打分，可能不如人手操作；建议 DIY 对局以 PvP 为主。
- 每个角色 8~24 种卡、上限合计 ≥ 40 张是硬性要求，否则无法开局。
- 上传频率限制：每 IP 每分钟 5 次；全服最多保存 200 个 DIY 角色。

## 7. 服务端实现要点（给自己接手时看）

- `shared/diy.js`：校验 + 注册（把角色注入 `Cards.PROFILES`，引擎/卡组校验/AI/渲染全部复用原版逻辑）+ 机制目录。
- `server/diy.js`：持久化 `data/diy-heroes.json`、REST 接口、启动时注册内置角色与已保存角色。
- `server/index.js`：房间 `pool` 字段、快速匹配同池、`Diy.isDiy(hero)` 的准入校验、连接时下发 `diy:list`。
- `test/diy.js`：校验器/注册/卡组/池分离/AI 实战冒烟。
- `test/diy-server.js`：接口 + 池分离的联机测试。
